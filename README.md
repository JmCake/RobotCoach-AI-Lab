# RobotCoach-AI-Lab

九页翻书课堂的存档版本已通过 [PR #11](https://github.com/JmCake/RobotCoach-AI-Lab/pull/11) 合入 main。

本项目基于原作者 [PumpkinKiller04/RobotCoachAI](https://github.com/PumpkinKiller04/RobotCoachAI) 的课程与交互设计进行精简改造，目标是将《机器人总教练请就位》从复杂的导学单网站，改造成**打开即可体验、单页顺序推进、以机器人互动为核心**的教学网站。

> **开发基线**：[完整实施计划与三个版本路线图](DEVELOPMENT_PLAN.md)。本实现从新仓库的方案基线开始，选择性复用原作者静态代码；不包含废弃的 Vue/TypeScript 仿真系统。

## 打开网站

需要 Node.js 18 或以上版本。生产页面没有第三方运行依赖，也没有后台服务。

```bash
git clone --branch codex/classroom-race-day https://github.com/JmCake/RobotCoach-AI-Lab.git
cd RobotCoach-AI-Lab
npm run dev
```

访问 **http://127.0.0.1:4180**，直接进入第一章。也可以在项目目录运行 `python -m http.server 4180`，再访问相同地址。请通过 HTTP 打开，不直接双击 HTML（浏览器对本地 ES 模块有限制）。手机访问时，可使用静态托管站点，或将 Python 服务的局域网地址用于同网设备。

## 第一章急弯对照

课堂展示可从 `/#diagnosis` 开始。请同学举手选择「能完赛」或「会失误」，再点「开始试跑」。第 3 页会把初代机实际停下的位置标在同一条跑道上。要切换到其他实验，打开右上角「课堂目录」即可。

从第 1 页用初代机试跑，第 2 页点击位置认识感官，并安装或卸下模块。机器人会显示实际安装的硬件。第 3 页用自己的配置试跑，与初代机共用急弯、40 m、目标速度 6.4 m/s、种子 2026，可切换配置和查看两份真实成绩。更改安装配置会清除学生配置的旧成绩。翻页后，未完成的试跑从起点重来。

本地可直接打开 `http://127.0.0.1:4180/#diagnosis` 或 `http://127.0.0.1:4180/#trial`。从试跑页打开独立 Demo 后，点击「返回课堂试跑」会一并带回在 Demo 中调整的传感器。

## 第二章人形短道

从 `/#manual` 手动跨过矮栏、从横梁下通过，去 `/#training` 进行 Q-learning，再在 `/#showcase` 比较同一批留出赛道的训练前后成绩。动作每 0.1 秒更新一次。策略选择前进、跳跃或下蹲，速度、姿态和落脚由规则控制。短道固定启用四种模拟传感器。

训练每批 300 轮，沿用同一份人形 Q 表继续学习。翻页或刷新会保留已经发生的更新和完成轮次，未完成的赛道回到起点。成绩对比页的实验条件里也可打开旧版 Runner，用原有本机记录继续练习。

运行 `node scripts/evaluate-motion-learning.mjs <JSON输出路径>` 可复现三组各 300 轮独立训练及每组 20 对冻结测试。训练赛道种子为 101–130，验证为 1001–1020，最终测试为 9001–9020。脚本记录逐轮实测、失败原因及模型指纹，并核对评估期间 Q 表没有变动。三组完赛数均由 0/20 提升至 20/20，平均越障数均由 0 提升至 3。[逐轮结果](docs/motion-learning-rounds.csv)

## 第 9 页连续总决赛

从 `/#design` 进入，选择第一章的感官配置或为本场调整，再主动选择「我的学习策略」或「规则参考」。本机学习策略来自训练页的兼容人形 Q 表，起跑时冻结。策略选择越障动作，底层规则负责速度、转向、姿态和落脚。

同一个机器人依次通过直道 24 m、障碍 30 m、弱光 28 m、急弯 44 m、凹凸 30 m、湿滑 34 m。坡面、路线、光照和摩擦按位置平滑衔接。倒计时和暂停不计入模拟成绩，首次碰撞、越界或摔倒锁定成绩。过线减速或失败后的动作会继续展示。同条件重试使用上一场原始配置和冻结策略。

成绩摘要保存在本机，最近一场完整记录保存在当前标签页，可下载 JSON。记录包含赛道、感官与策略快照、10 Hz 决策和事件，以及从起跑到展示结束的 120 Hz 姿态样本。样本的数值保留六位小数。展开总决赛页的旧实验入口可继续使用 V2 综合挑战、图形化方案和课程总结。

运行 `node scripts/capture-final-race.mjs <输出目录>` 可复现规则完赛、实际失败和学习策略迁移三场样例。脚本仅重新生成一份第 7 页模型用于总决赛迁移，不再运行第二章的留出对照。种子 2026、四感官下，规则参考用时 40.90 秒，冻结学习策略用时 38.74 秒，两者均越障 6 次并完成 190 m。规则参考仅开摄像头时在 26.78 m 撞栏并倒地。[实测摘要](docs/final-race-evidence.json)

## 独立人形运动 Demo

线上分享地址：**[打开机器人跑道](https://jmcake.github.io/RobotCoach-AI-Lab/)**，也可访问 [`demo-motion.html`](https://jmcake.github.io/RobotCoach-AI-Lab/demo-motion.html)。原课程保留在 [`course.html`](https://jmcake.github.io/RobotCoach-AI-Lab/course.html)。

推送到 `codex/humanoid-motion-demo` 会触发 `.github/workflows/pages.yml`：先执行单元测试、语法检查和运动 Demo 浏览器回归，再构建并发布到 GitHub Pages。测试失败不会发布。以后将此工作流随 PR 合并到 `main` 后，`main` 的推送也会自动发布。当前无需合并 PR 即可更新线上跑道。

部署构建使用 `npm run build:motion`：生成完整静态 `dist/`，把跑道复制为首页，原课程首页另存为 `course.html`，保留独立入口与许可文件。普通 `npm run build` 和本地开发入口不变。浏览器无业务后端依赖；Pages 只是静态文件托管。

独立入口 **`http://127.0.0.1:4180/demo-motion.html`** 从直道开始，传感器默认关闭。`npm run build` 会将此入口一起打包到 `dist/`。

支持直道、急弯、湿滑、凹凸、障碍与弱光六种环境；开始/暂停、重置、慢放，四种传感器独立开关及总开关，以及折叠的种子、目标速度与连续重试设置。机器人具有肩肘、髋膝踝关节、支撑脚固定与摆动脚抬落，能跳栏、收身、失衡纠偏、连续踉跄、摔倒停留并撑地起身。

默认目标速度 **6.4 m/s**，每次挑战 **40 m**。初次打开从直道和全关闭的传感器开始，按“直道 → 障碍 → 弱光 → 急弯 → 凹凸 → 湿滑”逐步体验。页面折叠的“教学顺序与模块参考（教师）”列出建议，不自动替学生安装模块。成功后可进入下一条跑道，保留已有选择。

| 教学顺序 | 建议配置 | 重点与替代方案 |
| --- | --- | --- |
| 1. 正常直道 | 无需传感器 | 认识基础步态 |
| 2. 障碍跑道 | 摄像头 + IMU | 感知障碍，并稳定起跳、落地和收身后的姿态；激光测距可替代摄像头 |
| 3. 弱光跑道 | 摄像头 + 激光测距 + IMU | 视觉受限时补充距离，保留跨越和落地的姿态反馈；激光可替代视觉避障 |
| 4. 急弯跑道 | 摄像头 + IMU | 看见弯道还要稳定姿态；只站得稳却跑出跑道也不算通过 |
| 5. 凹凸路面 | IMU + 足底力觉，可保留摄像头 | 既测身体倾斜，也缓冲落脚；IMU 不能替代腿部缓冲 |
| 6. 湿滑路面 | 摄像头 + IMU + 足底力觉 | 标准演示中 IMU 是稳定打滑后姿态的必要模块；摄像头提前减速，足底力觉反馈滑移 |

必须实际穿过格纹终点线，且这一段无摔倒、碰撞和越界才显示成功、成绩与成功对白，随后平滑减速停下。碰撞、摔倒或越界发生时立即锁定本轮失败，即使惯性使身体经过终点、或者后来打开模块，也不会改成成功。默认在失败后停留供观察，点击“回起点重试”才重新挑战。

可展开设置，选择“自动回起点重试（保留失败记录）”。每次都重建同一种子的完整跑道，起点为 0、终点固定 40 m；保留累计摔倒、累计碰撞、上轮结果和最近 20 次尝试，不再移动终点或丢掉上轮碰撞。已经成功后若更改模块，会清除旧成功状态并准备新配置的一轮挑战。

凹凸路面新增落脚能量导致的腿部压缩：足底反馈通过落脚补偿和减速降低冲击；过度压缩会让膝部下沉、踉跄、摔倒。失败依据实际受力，不检查是否缺少指定模块。默认条件下，种子 1–20 中推荐配置均通过；凹凸保留摄像头和 IMU、仅关闭足底力觉为 **0/20**，加入后 **20/20**。这个结论只适用于列出的速度、路长与种子，不是所有配置下的保证。

越障跳跃加入前倾角动量：起跳冲量随水平速度和垂向起跳速度变化，落地冲量随水平速度与实际落地垂向速度变化，IMU 通过已有倾角/角速度反馈力矩来抵消。所有配置承受相同冲量，关闭 IMU 不直接触发失败。默认 6.4 m/s、40 m、种子 1–20 中，障碍关仅摄像头为 **0/20**（实际越过矮栏、无碰撞，落地后失衡摔倒），摄像头 + IMU 为 **20/20**；弱光使用测距但关闭 IMU 也会在落地后失衡，加入 IMU 为 **20/20**。摔倒自述会说“我跳过去了，可落地时身体往前倒，没及时稳住”，与没看清撞上障碍区分。

实体碰撞的转动冲量按实际撞击速度和接触部位计算，头部接触采用更长的倾覆力臂。默认速度下，弱光关闭 IMU 的腿部或头部碰撞会产生明显失衡与摔倒；有 IMU 即使扶住身体，也不能抹掉本轮的碰撞失败。终点前一步碰撞的边界情形、自动重试保留记录，以及成功后换配置清除旧成绩均有回归检查。

雨水关的滑移按跑速和实际摩擦计算，不再把摄像头减速后的 2.65 m/s 当成完全不滑。标准目标 6.4 m/s、40 m、种子 1–20 中，摄像头 + 足底力觉、关闭 IMU 为 **0/20**，加入 IMU 后 **20/20**；即使已减速且感到脚滑，缺少姿态反馈仍会持续倾斜并摔倒。IMU 不改变摩擦和滑移，只通过反馈力矩纠正身体。教学对照固定标准条件；自行调到 2 m/s 属于另一个低速实验，不代表默认雨水关不需要 IMU。

| 传感器 | 模拟观测与实际作用 |
| --- | --- |
| 摄像头 | 看弯道、跑偏和湿滑路面，规划转向与提前减速；弱光视距 1.05 m、反应延迟 0.2 s |
| 激光测距 | 7.5 m 范围的障碍测距，辅助跨栏与收身；关闭摄像头后仍可测距 |
| 姿态传感器 IMU | 倾斜与角速度，产生实际纠偏力矩；关闭后纠偏力矩为零 |
| 足底力觉 | 触地、落脚高度差与滑移，调节减速和落脚补偿；不读取前方地形 |

各模块显示作用、当前读数及关闭状态，可以在运行中逐一关闭，并在重置或切换场景后保留选择。全部关闭时没有障碍观测，不会继续偷偷使用摄像头；单独摄像头仍可在明亮环境识别近处障碍，弱光下与激光测距存在实际差异。

摔倒时，机器人会用气泡自述感受，例如“脚底悄悄滑走了，我还以为自己踩得很稳”。对白根据实际失衡/碰撞原因、当时的传感器配置与控制动作选取，不直接说该开启哪个模块；已有感知仍失败时也会如实描述。对白在发生时固定，事后切换模块不会改写原因，连续重试会产生新的自述，重置清除提示。本机有中文语音时可自动朗读并单独关闭；只使用本地中文声音，不依赖在线语音，没有可用声音时保留文字。

运动采用固定 120 Hz 的简化模型，辅助实际改变测距范围、限速、姿态力矩与落脚补偿。弱光基础视觉有短视距与反应延迟；障碍依据脚部高度和收身高度判定碰撞，标示小腿或头部位置。该 Demo 使用模拟观测与简化动力学，不是像素视觉、真实双足机器人动力学或训练效果。低速/直道关闭辅助也能稳定，开启辅助不能倒转已经发生的摔倒。

定向验收：`node --test tests/motion.test.mjs`、`npm run test:e2e -- tests/e2e/motion.spec.js`。同条件比较可选湿滑环境，关闭辅助运行，再重置并开启辅助；保持种子与目标速度一致。

复现完整配置对照：`node scripts/evaluate-motion.mjs`，默认将 JSON 保存到系统临时目录，也可传入输出文件绝对路径。实际执行六场景 × 全部 16 种感官组合 × 20 个种子，共 **1,920 次**独立尝试，记录距离、用时、腿部压缩、碰撞、越界、摔倒与真实过线结果。

## V2.0 综合升级

课堂共三章 9 页。感官介绍与安装在同一页，闭环组装和断开测试共用一张图。总决赛页保留旧版综合挑战入口，原五项图形化设计与总结可在该入口展开。课堂沿用原作者机器人、书本色彩和深色 Canvas。

- **自主控制与复杂环境**：复用 Runner、重力/跳跃常量、碰撞几何、奖励账本、机器人绘制与 Learner 的 Bellman 更新；渐进增加固定/动态横梁、三种高度地面障碍、湿滑速度漂移与起跳变化、弱光视距。没有引入新的运行依赖或废弃仿真代码。
- **观测与融合**：视觉受光照、视距与量化误差限制；高低两束测距区分障碍距离；IMU 提供高度、速度、垂向运动与滑移信号，足底力觉提供触地和载荷。只有 `observe()` 可检查场景；策略接收脱离世界的观测对象。关闭的传感器输出 null，V2 禁止使用旧 `Runner.state()` 读取真值。
- **真实行为克隆**：采集随机训练环境中的专家观测/动作，每三条取一条，保留约 4500 条；监督训练决策树，80% 样本训练、20% 样本留出检查动作一致率。运行时只读取学出的树，不回放时序，也不回退到专家。动作一致率不代表任务成功率，后者另由冻结赛道测试计算。
- **独立 Q-learning**：V2 使用独立空表和观测状态，不读示范或 V1 Q 表；每点一次执行最多 100,000 次实际奖励更新，失败记录后开始下一轮。可暂停、清空、继续训练，最近真实奖励和 Q 更新可展开查看。
- **综合挑战与比较**：选择感官、策略、四种环境与赛道种子即可运行；比较在相同环境/感官、相同 9001–9020 种子下，分别冻结运行规则、模仿和 Q 策略各 20 轮，显示成功率、碰撞轮数、平均跨障碍、完成进度。未训练策略如实失败，不补装成功策略。
- **本地恢复**：V2 独立存储 `robotcoach:challenge:v2`，保留 V1 所有数据；离页/隐藏暂停并同步保存，多标签页更新会同步并暂停旧页。导出 JSON 包含观测动作样本、模型、Q 表、真实更新、种子、逐轮成绩和传感器条件。

复现：`npm run evaluate:v2`（默认输出系统临时目录；可用 `EVIDENCE_DIR` 指定目录）。脚本从空表独立训练种子 17、42、2026，每组 100,000 次更新；训练赛道使用 101–130 随机光照/摩擦/速度/横梁组合，测试使用不重合的 9001–9020。六种感官组合 × 四种环境 × 四份策略（含空表基线）× 20 轮 × 三次训练，共 **5760 轮冻结实测**。CI 执行同一脚本并上传完整 JSON；页面内比较只测当前环境的三份策略。任务定义为存活 1800 个固定物理帧（约 30 秒）；完成进度为已运行物理帧 / 1800，碰撞即本轮失败，跨障碍按实际通过数量计数。

| 实测条件 | 规则 | 行为克隆 | 空表 Q | 训练后 Q |
| --- | --- | --- | --- | --- |
| 完整感官，四种环境（各 20 轮，三组训练） | 100% | 100% | 0% | 100% |
| 弱光环境，仅摄像头（种子 42 模型） | 100% | 100% | 0% | 0% |
| 弱光环境，关闭 IMU（种子 42 模型） | 100% | 100% | 0% | 0% |
| 弱光环境，无感官（种子 42 模型） | 0% | 0% | 0% | 0% |

完整感官下，各环境平均跨障碍为 17.85 / 18.05 / 18.20 / 18.20；三组 Q 完成训练轮次为 650 / 594 / 645。行为克隆用 3600 条样本训练，900 条留出动作一致率约 99.89%。上述感官消融沿用完整感官训练的冻结模型，未为缺失感官重新训练；Q 退化表明输入分布变化会失效。某些规则与感官具有冗余，关闭单个感官未必失败，增加感官也不保证学会。

验证通过：21 项算法测试、34 项真实浏览器测试、JavaScript 语法检查及静态构建；另在 `SERVE_DIST=1` 下通过 3 项设计/训练/触屏交互测试。桌面 1280×720、手机 390×844 与 320×740 覆盖页面身份、非空内容、控制台、截图、操作、恢复与暂停。Browser plugin not available，本次使用现有 Playwright 与本机 Chromium；实体手机、Safari/Firefox 尚未验证。原生 JavaScript 项目没有独立 TypeScript 类型检查，使用语法与运行测试。

**边界**：这是有真实动作、碰撞和奖励的二维教学仿真；未实现三维双足动力学、实体传感器、转弯导航或通用机器人部署。湿滑与动态横梁属于本版验证的复杂环境。所测 100% 仅限所列环境和种子；不意味着真实世界或任意配置成功。原有教学机制演示继续明确标注。

## 学习算法与演示边界

- 第一章试跑沿用原版的**教学机制演示**，不宣称真实传感器仿真或物理验证；页面明确标注。
- 行为克隆页通过“示范与环境变化”说明模仿局限，使用标明性质的动作回放，此原理页**没有独立行为克隆训练模型**；V2 综合挑战另有真正训练的独立模型。
- Q-learning 从空 Q 表开始，根据距离、障碍类别、跳跃状态和速度选择等待、跳跃或下蹲。实际执行 `Q ← Q + α[r + γ max Q′ − Q]`（α=0.2，γ=0.95），终止时不自举；没有预置成功策略或专家数据。越过障碍 +8，碰撞 −12，完整跑完 1800 帧 +4；起跳 −0.03，下蹲决策 −0.002，等待不加分。物理、障碍分布和碰撞判定保持 V1.0 标准。
- 成果页冻结 Q 表、关闭探索，展示实际策略。训练不保证每轮成功；记录保留最近 150 轮，清空浏览器数据会丢失本地进度。

## V1.1 训练与体验增强

训练页与成果页可执行「比较训练前后」：用相同种子 9001–9020，各运行 20 轮，关闭探索并冻结两份 Q 表，显示平均分、平均跨障碍数、完整跑完率和失败原因。起点是进入 V1.1 时保存的实际策略；新训练从空表起步，已有 V1.0 经验、成绩和历史继续保留。重置同时清空策略、基线、更新记录与比较结果。训练页保存比较，成果页不写入训练数据；比较支持取消，离页自动停止。

页面显示最近轮次的结果趋势，展开可查看奖励构成和最近 12 次实际 Q 更新。新旧奖励记录分开统计；未测到提升时如实显示。另一训练标签页保存或重置后，当前页同步并暂停，避免旧策略覆盖新数据。

手控按 60Hz 固定物理更新，触屏按下即接收跳跃，支持落地前 130ms 输入缓冲和下蹲切换；手机可真正拖拽安装传感器，也可直接点选。开场跑酷采用固定时间步，适配不同刷新率；操场纹理固定以消除闪烁，奖励曲线按设备宽度绘制。训练图表与文字减少重复绘制，保留原版风格与三章 11 页。

复现训练：`npm run evaluate -- /绝对路径/training-results.json`。三组种子 17、42、2026 独立从空表训练，每组 100,000 次更新；各 20 轮冻结测试平均跨障碍数均 **0 → 18**，完整跑完率均 **0% → 100%**。完成训练轮次分别为 548、566、581；1,000 次更新时平均跨障碍仅 1.20、0、0.85，说明早期仍会失败。此结果仅适用于当前跑酷环境与这组测试种子，完整跑完指存活 1800 帧，属于 V1.1 同条件对照，不代表 V2.0 的泛化能力。

V1.1 的 14 项算法测试、28 项浏览器测试、JavaScript 语法检查及构建通过，覆盖原有三章流程、固定种子比较、奖励核算、取消/重置、旧数据恢复、标签页同步、原生触屏拖拽、320px 窄屏、32 倍训练响应和隐藏暂停。桌面 1365×1100 与手机 390×844 截图检查无页面溢出或控制台错误。使用 Chromium 桌面与手机触屏模拟；实体手机、Safari/Firefox 尚未验证。当前会话未提供 Browser 插件，因此使用仓库 Playwright 流程进行验证。

## 开发与测试

```bash
npm ci
npx playwright install chromium
npm test
npm run check
npm run test:e2e
npm run build
```

`npm test` 为算法检查，`npm run check` 检查原生 JavaScript 语法；Playwright 为真实 Chromium 交互测试，包含桌面、手机视口和触屏模拟；`dist/` 是可部署到任意静态服务器的完整产物。`npm run evaluate -- /绝对路径/training-results.json` 可复现 V1.1 的训练与五个训练检查点；`node scripts/generate-videos.mjs` 可重新生成四段自有图形演示视频。已有本机 Chromium 时，可通过 `PLAYWRIGHT_CHROMIUM_EXECUTABLE` 指定其路径；端口被占用时可设置 `PORT`，如 4182。

本地验收：7 项算法测试、20 项浏览器测试通过，另检查构建产物和 320px 窄屏。PR 审查修复了快速切页未保存最新训练、旧手控/展示标签页覆盖新训练、按钮焦点导致方向键失效、反馈动画提前返回、绘制修改仿真状态和评估随机流不独立的问题，详见 [审查记录](docs/V1_REVIEW.md)。浏览器实录的早期训练仍有碰撞；更正逐轮独立种子后，100,000 次更新的三组冻结测试平均跨障碍数为 17.90、18.00、14.15（训练前为 0）。这不是 V1.1 的训练优化或 V2.0 泛化验证。

## 产品目标

保留原作者的三章教学逻辑与核心交互：**感知 → 学习 → 闭环**。

- **第一章｜感知与选拔**：初代机器人诊断、认识感官、安装传感器、升级试跑与结果对比。
- **第二章｜学习与训练**：行为克隆原理、人工控制、Q-learning 自主试错、奖励反馈、训练成果展示。
- **第三章｜决策与闭环**：闭环拼装、关闭节点观察故障、综合场景设计与课程总结。

网站以一页一页的方式推进，每页只围绕一个主要任务，形成 **简短讲解 → 直接操作 → 观察反馈 → 下一页** 的流程。顶部仅保留简洁章节导航；页面切换使用轻量淡入/位移动画，**不做左右双页，也不做复杂翻书特效**。
