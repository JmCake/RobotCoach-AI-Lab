## 3. 实现要求

### 第 1 页：初代机，为什么跑出了弯道？

初始条件：急弯、40 m、目标速度 6.4 m/s、种子 2026；初代配置候选为仅摄像头开启。实际运行确认，禁止根据缺少传感器直接设置失败。

一个明确的开始/重试主操作，连续展示奔跑、失衡、越界、摔倒或真实过线。失败锁定后继续完成倒地动作，惯性过线不改判成功。

初代配置仅用于本页临时实验，不覆盖学生保存的选择。若工况需要调整，必须与第 4 页同步并说明原因，不做两套难度。

### 第 3 页：保留安装操作

只做第 4 页读取所需的最小映射。核对课程雷达/测距字段与 motion lidar 的含义；保存学生选择，不自动补装模块，不改旧学习数据。

### 第 4 页：同一条弯道，这次会怎样？

直接嵌入共享组件，读取学生配置；场景、种子、长度、目标速度和控制器版本与初代对照一致。可依次运行初代/当前对照，不要求首轮开发双屏同步或回放。

所有成绩来自实际运行并绑定配置快照。未跑显示“尚未测试”；配置改变不沿用旧成功状态；初代对照不污染学生配置。保留独立 Demo 入口，旧简化试跑不再作为并列主实验。

### 组件、存储与路径

复用 assets/motion/world.js、rig.js、render.js，不复制物理、不引入新框架；按当前架构选择改动更小的 iframe 或模块挂载方式。封装配置输入、开始、暂停、重试、结果输出和销毁。

离页/隐藏时暂停或销毁循环与监听器，返回恢复配置；未完成尝试可以明确从起点重来，不让后台偷偷运行。使用 iframe 时校验 postMessage 来源和结构。

书页默认不自动朗读，保留文字反馈；独立 Demo 既有行为不无关改动。窄屏 Canvas 与按钮可操作，不横向溢出。

分别处理普通构建和 build:motion 的课程入口；不假定 course.html 在所有构建存在。不保留相关活动中误指向 Demo 首页的 index.html#design，只修本轮相关路径，不重构全站路由。
