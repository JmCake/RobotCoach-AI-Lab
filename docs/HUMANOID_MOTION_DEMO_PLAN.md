# 人形机器人跑道运动动画 Demo｜独立原型方案

## 目标与开发边界
在现有 RobotCoach-AI-Lab V2.0 基础上，先制作一个**可单独打开预览的 HTML 动画原型**，验证人形机器人在不同跑道条件下的动作、失衡与摔倒效果，**暂不并入三章 11 页课程，不修改已有课程导航和实验逻辑**。新页面建议为仓库根目录 `demo-motion.html`，共享已有视觉资源时优先复用，不另起一套网站。代码以原生 HTML/CSS/JavaScript + Canvas 2D 为主，无须引入大型框架、三维引擎或服务器。

## 主角必须是人形机器人
- 使用与现有项目视觉风格一致的**双足人形机器人**，明确具备头部、躯干、肩、肘、髋、膝、踝、双臂、双腿、足部，不做轮式机器人、玩具小车或整个图片水平滑动。
- 优先查阅并复用现有 `assets/robot.svg`、`assets/robot-dom.js`、`assets/runner-render.js` 等可以利用的造型和绘制代码；需要时为肢体创建分层/关节结构以便独立变形。保留原创作品的颜色与气质。
- 至少具备：左右交替迈步、摆臂、脚掌着地与离地、身体重心上下起伏、加减速、转弯侧倾、失衡纠正、连续踉跄、摔倒后的短暂停留、重新起身或重置。
- 动作须连续插值；抖动应是有原因和幅度变化的失衡信号，不要用无规律画面震动代替，也不能突然切成一张“倒地图片”。

## 场景与可观察的运动差异
1. **正常直道**：稳定双足跑步、自然步频、手臂反向摆动。
2. **急弯跑道**：转向不足、躯干侧倾、脚步调整；辅助关闭时可逐渐踉跄并跑偏/摔倒。
3. **湿滑路面**：足部打滑、摆臂补偿、步频变化、失衡后跌倒；辅助开启可提前减速、尝试恢复平衡。
4. **凹凸路面**：脚落点高低变化、身体颠簸、踝膝协调不足产生跌绊。
5. **障碍跑道**：遇到障碍时跳跃、下蹲或躲避，失误时真实碰撞、绊倒；提示碰撞位置。
6. **弱光跑道**：可见距离缩短、识别反应滞后，观察视觉信息不足造成的避障差异。

以上是场景预设，演示中应支持重试与重复播放；相同场景参数和随机种子下可以复现主要运动结果。

## 运动与传感器辅助逻辑
- 在 Canvas 实现轻量、稳定的时间步进模拟，管理位置、速度、步态相位、脚部接触、倾斜角/角速度、摩擦系数、障碍距离与碰撞、摔倒阈值及状态机（跑步→失衡→踉跄→跌倒→停止/起身）。可以用简化动力学和插值实现可信动画，不宣称真实人形机器人动力学。
- **开启/关闭传感器辅助必须改变实际控制输入或观测**，如前方障碍检测距离、姿态反馈与纠偏、湿滑场景限速、落脚补偿，而非根据开关直接播放“成功/失败”预制动画。辅助有改进但不保证任何条件下必定成功。
- 展示清晰的条件与结果，例如“失衡角度 / 运动状态 / 碰撞原因”等必要反馈；技术调参可折叠，保持操作界面简洁。
- 不把 V2.0 的历史训练效果或传感器数据伪称为本 Demo 的真实学习结果。本原型首先验证动画与轻量运动控制，未来再讨论如何接入已有感知、训练与综合挑战引擎。

## 页面交互和视觉
- 单场景大跑道画面为主；保留现有项目的红色跑道、色调、机器人亲和造型，支持桌面与手机布局。
- 必备控制：场景选择、开始/暂停、重置、传感器辅助开关。可以加入慢放或同种子前后对比，但不能以增加功能为由堆积控件与说明文字。
- 跑道、弯道、路面不平、障碍和光线变化应通过画面本身可见，学生能凭视觉分辨场景。
- 确保 Canvas 图层适配像素比与容器尺寸，动画平滑，资源本地加载，不依赖外网。

## 交付与验收
1. 创建独立可直接经本地 HTTP 服务预览的 `demo-motion.html`，必要时新增独立 JS/CSS 及最少量可复用工具代码；暂不链接到现有三章页面、不修改课程顺序。
2. 六个场景可切换；人形关节动画自然，失衡、踉跄、跌倒是连续过程；辅助开关能改变控制行为且场景可重置。
3. 最少进行 JavaScript 语法检查、桌面与手机浏览器运行检查，以及正常跑步、失衡摔倒、辅助差异三类关键场景验证；避免重复全面审查现有课程。
4. 在独立开发分支提交 PR，**不自动合并**。交付预览地址或本地运行命令、主要效果截图及简短说明，待看过视觉效果后再决定是否整合进入课程。
